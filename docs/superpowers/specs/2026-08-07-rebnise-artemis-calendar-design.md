# 鹿児島レブナイズ・アルテミス北海道 カレンダー登録サイト 設計

作成日: 2026-08-07

## 目的

鹿児島レブナイズ（B.LEAGUE ONE / バスケットボール）とアルテミス北海道（V.LEAGUE Women / バレーボール）の試合予定を一覧表示し、クリック操作でファンが自分のGoogleカレンダーに登録できる公開サイトを作る。

## 前提と制約

- **公開範囲**: ファン向けに一般公開する
- **公式のデータ配信は存在しない**: 両チームとも公式サイトに日程は掲載されているが、ics配信もAPIも提供していない。したがって日程データは自前で保持する
- **ホスティング**: GitHub Pages（無料・HTTPS・独自ドメイン可・`.ics` を固定URLで配信できる）
- **データ更新**: リポジトリ内のJSONファイルを手動編集してpushする
- **想定閲覧環境**: スマートフォンでその場で登録する使い方を主とし、モバイルファーストで設計する

## スコープ

対象は両チームの全試合。プレシーズン・レギュラーシーズン・ポストシーズンを含み、HOME/AWAY の両方を載せる。フィルタで絞り込めるようにする。

## 技術選定

素の HTML / CSS / JavaScript と JSON データファイルで構成する。ビルド不要でGitHub Pagesにそのまま配置できることを優先する。React等のフレームワークはこの規模に対して過剰であり採用しない。

唯一のビルド処理は「JSON から購読用 `.ics` を生成する Node スクリプト」のみ。

### GASを採用しない理由

Google Apps Script でもウェブアプリとして公開はできるが、本要件では以下が満たせない。

| 満たせない要件 | 理由 |
|---|---|
| 購読型URL（webcal） | GASウェブアプリのURLは `script.googleusercontent.com` へ302リダイレクトする仕様で、Googleカレンダーの「URLで追加」がこれを追えず失敗しやすい |
| `.ics` の一括ダウンロード | HtmlService は iframe サンドボックス内で動作し、ブラウザのファイル保存が制限され不安定 |
| 独自ドメイン・短いURL | `script.google.com/macros/s/...` の長大なURLしか持てない |
| SNSシェア時のカード表示（OGP） | GASは対応不可 |
| 表示速度・アクセス数 | 初回ロードが遅く、無料枠に実行回数上限がある |

なお「スプレッドシートを日程マスタにして GitHub Actions で自動反映する」ハイブリッド構成も検討したが、今回は仕組みの単純さを優先してJSON直編集を採用した。データ形式を保つ限り、後からこの構成に差し替えることは可能。

## ディレクトリ構成

```
/
├── index.html              サイト本体（1ページ）
├── style.css
├── app.js                  一覧描画・フィルタ・選択状態の管理
├── lib/                    ブラウザ・Node両用の共通モジュール（すべてESM）
│   ├── datetime.js         JST→UTC変換・終了時刻の算出
│   ├── ical.js             icsのエスケープ・行折り返し・カレンダー組み立て
│   ├── google-link.js      Googleカレンダーのテンプレートリンク生成
│   └── schedule.js         日程JSONの形式検証
├── data/
│   ├── rebnise.json        鹿児島レブナイズ 2026-27 全試合
│   └── artemis.json        アルテミス北海道 2026-27 全試合
├── calendars/              生成物（購読用・リポジトリにコミットする）
│   ├── rebnise.ics
│   ├── artemis.ics
│   └── all.ics
├── scripts/
│   └── build-ics.js        JSON → calendars/*.ics
├── test/                   node:test による変換処理のテスト
├── package.json
└── README.md               更新手順
```

拡張子は `.mjs` ではなく `.js` に統一する（`package.json` に `"type": "module"` を置く）。ローカル開発サーバが `.mjs` のMIMEタイプを解決できず、ブラウザがモジュールの読み込みを拒否するため。

### 各ユニットの責務

- **`data/*.json`** — 日程データの唯一の情報源。他のどのファイルもこれを書き換えない
- **`scripts/build-ics.js`** — JSONを読み、購読用 `.ics` を `calendars/` に書き出す。ブラウザ非依存
- **`app.js`** — JSONを読んで画面を描画し、フィルタと選択状態を管理する。変換処理そのものは持たず `lib/` に委譲する
- **`lib/*.js`** — 日時変換とics生成の中核。Nodeスクリプトとブラウザの両方から同じコードを使う。ここだけをテスト対象とする

## データ形式

`data/*.json` は次の構造を持つ。

```json
{
  "team": "鹿児島レブナイズ",
  "teamShort": "レブナイズ",
  "sport": "basketball",
  "season": "2026-27",
  "games": [
    {
      "id": "reb-20260926",
      "date": "2026-09-26",
      "start": "15:05",
      "end": null,
      "opponent": "ライジングゼファー福岡",
      "venue": "鹿児島県総合体育センター体育館",
      "homeAway": "home",
      "category": "regular",
      "note": ""
    }
  ]
}
```

- `sport`: `"basketball"` | `"volleyball"`
- `homeAway`: `"home"` | `"away"`
- `category`: `"preseason"` | `"regular"` | `"postseason"`
- `start`: `"HH:MM"`、または開始時刻が未発表の場合は `null`（後述の「時間未定の試合」を参照）
- `end`: `null` の場合は競技別のデフォルト所要時間で算出する（バスケットボール 2時間 / バレーボール 2.5時間）。個別に指定したい試合のみ `"HH:MM"` を書く。`start` が `null` のときは `end` も必ず `null` にする
- `id`: 予定の一意キー。ics の UID に使うため、一度公開した試合のIDは変更しない
- タイムゾーンは Asia/Tokyo 固定

### 時間未定の試合

リーグ戦後半など、日付だけ先に発表され開始時刻が未定の試合がある。この場合 `start` を `null` にし、**終日予定**として扱う。

- 一覧では時刻の代わりに「時間未定」と表示する
- カレンダーには終日予定として登録する（ics は `DTSTART;VALUE=DATE:`、Googleリンクは `dates=YYYYMMDD/翌日`）
- 後日時刻が発表されたら `start` を埋めて再ビルドする。`id` すなわち `UID` は変わらないため、**すでに購読している人のカレンダーでは終日予定が時刻入りの予定に自動で書き換わる**

仮の時刻で埋めることはしない。誤情報になるため。

### 初期データの投入

初期データは公式サイトおよび公式ニュース記事から収集して投入する。ただし以下の理由で取りこぼしと誤りが発生しやすいため、**公開前に人による目視照合を必須とする**。

- レブナイズのスケジュールページはJavaScriptで動的描画されており、機械的な全件取得が困難
- プレシーズンの日時・会場は個別のコラム記事に分散している

## 画面設計

単一ページ。上から順に以下を配置する。

1. **ヘッダー** — サイト名
2. **購読セクション** — 「シーズン全体を購読」ボタン（レブナイズ / アルテミス / 両方の3つ）
3. **チーム切替** — レブナイズ / アルテミス / 両方
4. **フィルタ** — カテゴリ（プレシーズン・レギュラー・ポストシーズン）、HOME/AWAY、月
5. **試合カード一覧** — 日付・曜日・時刻・対戦相手・会場・HOME/AWAYバッジ・カテゴリバッジ
6. **下部固定バー** — 選択件数と「選択した N 試合を .ics でダウンロード」ボタン（1件以上選択時のみ表示）

終了した試合はデフォルトで非表示とし、「過去の試合も表示」トグルで表示できる。

## カレンダー登録の3方式

### ① 1試合ずつGoogleカレンダーに追加

各試合カードのボタンから、Googleカレンダーの予定作成画面を開く。

```
https://calendar.google.com/calendar/render?action=TEMPLATE
  &text=<タイトル>
  &dates=<開始UTC>/<終了UTC>
  &location=<会場>
  &details=<補足>
```

- 日時は `YYYYMMDDTHHMMSSZ` 形式のUTCに変換して渡す（TZ指定より確実に動く）
- タイトル例: `レブナイズ vs ライジングゼファー福岡（HOME）`
- リンクは `target="_blank" rel="noopener"` で開く

### ② 選択した試合をまとめて .ics

各カードのチェックボックスで選び、下部固定バーからダウンロードする。ブラウザ側で `lib/ical.mjs` を使って ics テキストを組み立て、Blob として保存する。Google以外（Apple、Outlook）でも利用できる。

### ③ 購読型URL（webcal）

`calendars/*.ics` を GitHub Pages 上の固定URLで配信し、`webcal://` リンクとして提供する。一度登録すれば以後の日程更新が自動で反映される。

反映は購読側（Google等）の取得タイミングに依存し、数時間〜1日程度かかる。この点は画面上に明記する。

### スマートフォンでの制約

主要な閲覧環境はスマートフォンだが、方式によって挙動が異なる。

| 方式 | iPhone | Android |
|---|---|---|
| ① Googleリンク | ブラウザでGoogleカレンダーの予定作成画面が開く | 同左（アプリに遷移する場合もある） |
| ② 選択して.ics | iOS標準カレンダーに取り込まれる（Googleカレンダーには入らない） | 端末のカレンダーアプリ次第 |
| ③ 購読 | iOS標準カレンダーが `webcal://` を受け取れる | **Googleカレンダーの「URLで追加」はPC版ブラウザにしかないため不可** |

したがってスマートフォンからGoogleカレンダーに登録する主経路は①である。③はパソコンからのみ設定できる旨を購読セクションに明記する。これはGoogle側の仕様であり、こちらでは回避できない。

## ics の仕様

- `VCALENDAR` に `VTIMEZONE`（Asia/Tokyo）を含め、`DTSTART;TZID=Asia/Tokyo:` 形式で出力する
- `UID` は `<game.id>@rebnise-artemis-calendar` という固定サフィックスで生成する。公開ドメインには依存させない（ドメイン変更で購読側の予定が重複するのを防ぐため）。更新時も同一UIDを保つことで、購読側では重複せず既存の予定が更新される
- `SUMMARY` / `LOCATION` / `DESCRIPTION` はRFC 5545に従い `,` `;` `\` `改行` をエスケープする
- 各行は75オクテットで折り返す（マルチバイト文字を分断しないこと）
- 改行コードは CRLF

## エラー処理

- JSONの取得に失敗した場合、一覧領域にエラーメッセージと再読み込み手段を表示する
- 選択0件のときは下部バー自体を表示しない（無効ボタンを出さない）

それ以外の異常系は扱わない。静的ファイルの配信のみで、ユーザー入力もサーバ処理も存在しないため。

## テスト

バグの発生源が集中する変換処理のみを `node:test` で検証する。UI全体のE2Eテストは本規模では費用対効果が合わないため実施しない。

- JST → UTC 変換（Googleリンク用）が正しいこと
- `end` が `null` のとき競技別デフォルト所要時間で終了時刻が算出されること
- ics のエスケープ（`,` `;` `\` 改行）が正しいこと
- 75オクテット行折り返しがマルチバイト文字を分断しないこと
- 同一 `id` から常に同一 `UID` が生成されること

## 運用手順

1. `data/*.json` を編集する
2. `npm test` を実行する
3. `npm run build` を実行して `calendars/*.ics` を再生成する
4. コミットしてpushする（GitHub Pagesが自動で反映）

この手順は README にも記載する。
