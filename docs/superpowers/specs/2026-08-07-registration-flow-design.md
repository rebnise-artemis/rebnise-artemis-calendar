# カレンダー登録導線の再設計 Design

前提となる設計は `2026-08-07-rebnise-artemis-calendar-design.md` にある。本書はそのうち「画面設計」と「カレンダー登録の3方式」を差し替える。ics の仕様、データ形式、タイムゾーンの扱いは変更しない。

## 背景

公開前の画面確認で、登録手段の使い分けが利用者に伝わらないことが分かった。

現状は1ページに3つの登録手段が並んでいる。最上部に購読セクション、各試合カードにチェックボックスと「Googleカレンダーに追加」ボタンの2つ。利用者から見ると操作の選択肢が3つあり、どれを押せばよいか判断できない。チェックボックスに至っては用途の説明がなく、1件チェックして下部バーが現れて初めて意味が分かる。

さらに優先順位が逆転している。前設計は「主要な閲覧環境はスマートフォン」「スマホからGoogleカレンダーに登録する主経路は各カードのボタン」と定めていたが、実際の画面ではパソコン限定の購読が最上部を占め、主経路はカードの中に埋もれていた。

購読ボタンの実装にも捻れがあった。リンクが `webcal://` のため、Macで押すとAppleカレンダーが開く。Googleカレンダーには入らない。「Googleカレンダーに登録できるサイト」を掲げながら、購読だけがGoogle以外へ飛んでいた。

## 決定

**サイトの主役を「シーズン全体をGoogleカレンダーに入れる」に定める。** 一部の試合だけ登録したい人を副次的な導線として分離する。

利用者にとって最良の状態は、全試合がGoogleカレンダーに入り、日程が変わっても追随することである。これを満たすのは購読だけである。ics のインポートでも全試合は入るが、会場や時刻が確定するたびに手動で入れ直す必要がある。

**1ページに1つの判断だけを置く。** トップで「シーズン全体か、個別か」を1回選ばせ、選んだ先の専用ページでは操作を1つに絞る。

同じ判断を2箇所に置かない。トップの `webcal://` リンクは購読と競合しない。行き先のアプリが違うことをラベルに書くため、Googleカレンダーを狙う利用者の判断には入ってこないからである。

### 受け入れる制約

Googleカレンダーに全試合を入れるには、購読でもインポートでもパソコンが必要である。GoogleカレンダーのスマートフォンアプリにはURL追加もインポートも存在しない。Google側の仕様であり回避できない。

主要な閲覧環境はスマートフォンなので、大多数の利用者はトップページで「今すぐは使えない機能」に出会う。これを隠さず明示し、その場で個別ページへ逃がす。端末判定による出し分けは行わない。画面幅は端末種別と一致しないため、条件分岐は誤りを生むだけで利用者の理解を助けない。

## 画面構成

### `index.html` — シーズン全体をGoogleカレンダーに入れる

上から順に配置する。

1. **ヘッダー** — サイト名
2. **見出し** — 「シーズン全体をGoogleカレンダーに入れる」
3. **価値の説明** — 2点を短く示す
   - 全試合がまとめて入る
   - パソコンで1回設定すれば、スマートフォンのGoogleカレンダーアプリにも表示される
4. **チーム選択** — 両チーム / レブナイズ / アルテミス。初期選択は「両チーム」（`calendars/all.ics`）とする。以下の方法1と方法2の両方に効く
5. **注意** — どちらの方法もパソコンから行う旨。Googleの仕様であることも書く
6. **方法1: URLで購読する**（おすすめ）
   - 一行の説明 — 日程や会場が変わったとき自動で反映される
   - 購読URLを読み取り専用の入力欄に常時表示し、「URLをコピー」ボタンを添える
   - 手順を番号付きで4段階
   - 反映はGoogle側の取得間隔に依存し、1日以上かかることがある旨
7. **方法2: ファイルを取り込む**
   - 一行の説明 — すぐに全部入るが、日程が変わったら取り込み直しが必要
   - 「ファイルをダウンロード」ボタン
   - 手順を番号付きで5段階
8. **他アプリ向けリンク** — 「Appleカレンダー・Outlookをお使いの方はこちら」として `webcal://` リンク
9. **個別ページへの導線** — 「今すぐスマートフォンで入れたい方は、試合を選んで登録」

購読URLは常に表示する。コピーボタンが働かない環境でも、利用者が自分で選択して写せる状態を保つため。

### 2つの方法を並べることについて

手段を1つに絞れないため、「どちらを操作すればよいか分からない」が再発する危険がある。これを避けるため、**2つを対等に並べず、番号を振って順序を付け、それぞれの違いを一行で書く**。利用者に選ばせるのではなく、選び方を先に示す。

方法1を先に置く理由は自動更新である。2027年4月の6試合は会場が未発表で、確定後にデータを更新する予定があるため、追随する手段を優先する。

方法2を載せる理由は、購読の初回反映が遅く「入らなかった」と誤解されうること、および取り込んだ予定が自分のカレンダーに入るため編集や通知設定ができることである。

### `games.html` — 試合を選んで登録

現行トップページの内容をそのまま移す。

1. **戻りリンク** — 「← シーズン全体を入れる」
2. **フィルタ** — チーム / 大会種別 / HOME・AWAY / 年月 / 過去の試合も表示
3. **試合カード一覧** — 日付・曜日・時刻・対戦相手・会場・バッジ、および「Googleカレンダーに追加」ボタン

カード内の操作要素は「Googleカレンダーに追加」1つだけとする。

年月フィルタは前設計の画面設計に含まれていたが実装されていなかった。ここで補う。

選択肢は日程データから生成する。月を固定で書かない。シーズンの範囲が変わってもコードを直さずに済む。

形はプルダウンとする。「すべての月」を含めて9個になるため、チップにするとスマートフォンでフィルタ欄が5行に達し、試合カードが押し下げられる。プルダウンなら1行に収まり、年をまたぐ選択肢に「2026年9月」と年を含めた完全なラベルを付けられる。見た目はチップに合わせ、「すべての月」以外を選んでいるときはチップの選択状態と同じ配色にする。

他のフィルタと同様、独立して働く。組み合わせた結果が0件のときは既存の「条件に合う試合がありません。」を表示する。

## 廃止するもの

**チェックボックスで選んで .ics を一括ダウンロードする手段を廃止する。**

各カードに操作要素が2つ並ぶことが、使い分けの分からなさの直接の原因だった。またこの手段は購読の下位互換である。全試合を入れたい人には購読があり、自動更新も付く。

失うのは「Apple や Outlook に好きな数試合だけ入れる」経路である。これらの利用者は `webcal://` による購読が使えるため、実害は小さいと判断する。

削除対象は、`index.html` の `.selection-bar`、`app.js` のチェックボックス生成・選択状態管理・下部バー描画・ダウンロード処理、および `app.js` から `lib/ical.js` への import である。

`lib/ical.js` 自体は残す。購読用 ics を生成する `scripts/build-ics.js` が使っている。

## webcal の扱い

`webcal://` は OS 既定のカレンダーアプリに渡されるプロトコルである。Mac では Apple カレンダー、Windows では Outlook が開く。Googleカレンダーには入らない。

したがって主役を **https の URL をコピーする導線** に置き換える。`webcal://` リンクは「Appleカレンダー・Outlookをお使いの方はこちら」と行き先を明記したうえで、副次的なリンクとして残す。これらの利用者にとってはワンクリックで完結する正当な近道であり、消す理由がない。

ラベルに行き先を書くことが条件である。「購読」とだけ書かれたボタンは、押した先で何が起きるか予測できず、Googleカレンダーを狙う利用者の誤操作を招く。

## ファイル構成

```
index.html        購読ページ
games.html        試合一覧ページ
subscribe.js      購読ページ用（URL組み立てとコピー）※新規
app.js            試合一覧ページ用（既存を縮小）
style.css         両ページ共有
lib/              変更なし
data/             変更なし
scripts/          変更なし
```

`app.js` は `games.html` からのみ読み込む。`lib/ical.js` はブラウザから参照されなくなり、Nodeのビルドスクリプト専用になる。

### `subscribe.js` の責務

購読URLの組み立てと、コピー操作の処理のみを持つ。

URLは現在地から組み立てる。公開先のドメインをコードに埋め込まない。

```js
const dir = window.location.pathname.replace(/[^/]*$/, '');
const httpsUrl = `${window.location.origin}${dir}${file}`;   // コピー用（Googleカレンダー向け）
const webcalUrl = `webcal://${window.location.host}${dir}${file}`; // Apple・Outlook向け
```

コピー用は `origin`（スキーム込み）から、`webcal://` は `host`（スキーム抜き）から組み立てる。両者で使う部分が異なる点に注意する。

これにより、ローカル確認でも公開環境でも同じコードが動く。

### コピー処理

`navigator.clipboard` はセキュアコンテキスト（https または localhost）でしか使えない。GitHub Pages は https なので本番では問題ないが、LAN経由の実機確認（`http://192.168.x.x:8000`）では利用できない。黙って失敗させないため、以下の順で処理する。

1. `navigator.clipboard` が使えればそれで書き込み、「コピーしました」を一時表示する
2. 使えなければ入力欄のテキストを選択状態にし、「コピーできませんでした。選択されたURLを手動でコピーしてください」と表示する

購読URLを読み取り専用の入力欄に常時表示するのは、この2番目の経路を成立させるためでもある。

## 文言

実装時の判断を減らすため、主要な文言を定める。

- 見出し: 「シーズン全体をGoogleカレンダーに入れる」
- 注意: 「どちらの方法もパソコンから行ってください。GoogleカレンダーのスマートフォンアプリにはURLで追加する機能もインポート機能もありません（Googleの仕様です）。」
- 方法1の見出し: 「方法1: URLで購読する」＋「おすすめ」の印
- 方法1の説明: 「日程や会場が変わったとき、自動で反映されます。」
- 方法1の手順:
  1. パソコンのブラウザでGoogleカレンダーを開く
  2. 左側の「他のカレンダー」の＋を押す
  3. 「URLで追加」を選ぶ
  4. 上のURLを貼り付けて「カレンダーを追加」を押す
- 反映時間: 「反映のタイミングはGoogle側が決めており、最初に表示されるまで1日以上かかることがあります。」
- 方法2の見出し: 「方法2: ファイルを取り込む」
- 方法2の説明: 「すぐに全部入ります。ただし日程が変わったときは、取り込み直しが必要です。」
- 方法2の手順:
  1. 上のボタンでファイルをダウンロードする
  2. パソコンのブラウザでGoogleカレンダーを開く
  3. 右上の歯車から「設定」を開く
  4. 左メニューの「インポート / エクスポート」を選ぶ
  5. ダウンロードしたファイルと追加先のカレンダーを選び、「インポート」を押す
- 他アプリ: 「Appleカレンダー・Outlookをお使いの方はこちら」
- 個別導線: 「今すぐスマートフォンで入れたい方は、試合を選んで登録できます」

## テスト

変換ロジック（`lib/`）に変更がないため、既存の52件をそのまま維持する。本変更でテストの追加も削除も行わない。

UIのE2Eテストは前設計の判断どおり実施しない。確認は実機での目視による。

## 確認項目

- トップページで3チーム分のURLが正しく切り替わる
- 「URLをコピー」が https 環境で動作する
- http 環境でコピーが失敗したとき、URLが選択され案内が出る
- コピーしたURLをGoogleカレンダーの「URLで追加」に貼ると、全試合が入る
- `games.html` でフィルタが動き、「Googleカレンダーに追加」からGoogleの予定作成画面が開く
- 両ページ間のリンクが双方向に通る
- スマートフォンで横スクロールが発生せず、注意書きと個別ページへの導線が読める
- カード内に操作要素が「Googleカレンダーに追加」以外に存在しない

## スコープ外

- 日程の自動取得。データ更新は引き続き `data/*.json` の手動編集による
- 端末種別による表示の出し分け
